📌 1. Project Motivation & Problem Statement

Why physical edge hardware solves a real-world developer experience (DevEx) bottleneck.

❌ The Problem in Modern Software Engineering

Software engineers manage dozens of active repositories simultaneously. Developers constantly suffer from cognitive load:

  • Leaving uncommitted/unpushed Git changes on local branches before closing laptops.
  • Accumulating gigabytes of dead build cache (node_modules, target, .venv).
  • Orphaned dev servers silently consuming local TCP ports (:3000, :5173, :8000).

✅ The IoT & Cloud Solution

DevDock IoT Sentinel transforms the developer's physical workspace by deploying an ambient Edge Hardware Station on a Raspberry Pi:

  • Zero Screen Distraction: Real-time peripheral LED status indicator for repository hygiene.
  • Edge-to-Cloud Telemetry: Sub-second MQTT pub/sub synchronizes local state with remote edge hardware.
  • Physical Hardware Interactivity: Instant visual triage without navigating terminal dashboards.

📐 2. System Architecture & Telemetry Pipeline

Distributed 4-tier edge-to-cloud computing pipeline.

1. Client / Desktop
DevDock (Tauri 2 / Rust)
Scans repos, Git status & ports
2. Ingestion / Event
Telemetry Dispatcher
Encodes JSON health payload
3. Cloud Broker
MQTT (HiveMQ / Port 1883/8883)
Topic: devdock/{id}/status
4. Edge Actuator
Raspberry Pi (Python Daemon)
Drives GPIO 17, 27, 22 LEDs

Data Lifecycle: When DevDock audits repositories on macOS/Windows, it evaluates dirty git branches, active ports, and cache bloat. It transmits a lightweight telemetry payload via MQTT over TLS. The Raspberry Pi Edge Daemon subscribes to the telemetry feed, processes state transitions, and toggles physical GPIO circuits.

🔌 3. Hardware Engineering & Circuit Schematics

Electrical calculations, Bill of Materials (BOM), and GPIO pin configuration.

⚡ Electrical Safety & Current Limiting

Raspberry Pi GPIO outputs operate at 3.3V DC logic level with a maximum safe current draw of 16mA per pin.

Applying Ohm's Law ($V = I \times R$) for standard 5mm LEDs (Forward voltage $V_F \approx 2.0V$): 

V_resistor = V_supply - V_LED = 3.3V - 2.0V = 1.3V
I_LED = V_resistor / R = 1.3V / 220Ω ≈ 5.9 mA

✅ Safe & Optimal: 5.9 mA provides bright visibility while drawing less than 38% of the maximum GPIO pin threshold.

💻 5. Software Implementation & Edge Daemon

        
Production-ready edge agent with auto-reconnection and robust exception handling.

      


      

        
🐍 Raspberry Pi Edge Daemon (pi_sentinel.py)

        

          Runs as a background systemd service on Linux, subscribing to the encrypted Cloud MQTT topic:
        

        
# /opt/devdock/pi_sentinel.py
import json
import time
import paho.mqtt.client as mqtt
from gpiozero import LED

# 1. GPIO Pin Definitions (BCM)
green_led  = LED(17)
yellow_led = LED(27)
red_led    = LED(22)

def reset_leds():
    green_led.off()
    yellow_led.off()
    red_led.off()

# 2. MQTT Callback upon message delivery
def on_message(client, userdata, msg):
    try:
        payload = json.loads(msg.payload.decode('utf-8'))
        status = payload.get("status", "clean")
        
        reset_leds()
        if status == "clean":
            green_led.on()
        elif status == "dirty":
            yellow_led.on()
        elif status == "error":
            red_led.on()
        elif status == "sync":
            yellow_led.blink(on_time=0.2, off_time=0.2, n=5)
            green_led.on()
    except Exception as e:
        print(f"[Edge Daemon Error] {e}")
        red_led.blink(on_time=0.1, off_time=0.1, n=3)

# 3. Connection & Event Loop with Auto-Reconnect
client = mqtt.Client(client_id="rpi-devdock-sentinel-01")
client.connect("broker.hivemq.com", 1883, keepalive=60)
client.subscribe("devdock/telemetry/status", qos=1)
client.on_message = on_message

print("🚀 DevDock Edge Sentinel Daemon active. Listening for telemetry...")
client.loop_forever()

      

    


    
    

      

        
🗺️ 6. End-to-End Implementation Roadmap

        
Structured 5-phase execution plan from prototyping to evaluation.

      


      

        

          PHASE 1
          

            
Hardware Breadboard Prototyping & GPIO Test

            
Assemble 3x LEDs with 220Ω resistors on half-size breadboard. Verify GPIO 17, 27, 22 pin toggling via local Python test harness.

          

        


        

          PHASE 2
          

            
Cloud MQTT Broker & Pub/Sub Contract

            
Deploy secure MQTT broker instance (HiveMQ Cloud / Mosquitto). Establish topic hierarchy (devdock/{client}/telemetry) with QoS 1.

          

        


        

          PHASE 3
          

            
DevDock Desktop Telemetry Module

            
Integrate MQTT publisher client into DevDock's Tauri/Rust backend. Broadcast repository status on Git change, port open, and cache clean.

          

        


        

          PHASE 4
          

            
Edge Daemon Hardening & Linux Systemd Service

            
Package Python edge daemon as an auto-starting Linux systemd service on Raspberry Pi with automatic WiFi reconnection.

          

        


        

          PHASE 5
          

            
Live Benchmarking, Presentation & Evaluation

            
Measure roundtrip latency (<120ms target). Conduct live hardware demonstration and submit academic project report.
