🚀 1. Step-by-Step Implementation Guide: What To Do

Follow these 4 simple steps to set up the physical hardware and connect it to DevDock.

STEP 1
🔌 Wire the Circuit
Place 3 LEDs (Green, Yellow, Red) on a breadboard. Connect a 220Ω resistor to each Anode (+), and wire common ground (-) to Arduino/Pi GND.
STEP 2
📥 Upload Firmware
Connect Arduino to computer via USB. Open hardware/arduino/DevDock_Hardware_Station.ino in Arduino IDE and click Upload (➔).
STEP 3
⚙️ Configure DevDock
Launch DevDock, navigate to Settings ➔ 📡 Hardware & IoT Station, and select the detected USB Serial Port (e.g. /dev/tty.usbmodem... or COM3).
STEP 4
✨ Test & Code
Click the test buttons (🟢 Test Clean, 🟡 Test Dirty) or simply code! The physical LEDs update automatically upon every Git state change.

📌 2. Project Motivation & Problem Statement

Why physical edge hardware solves a real-world developer experience (DevEx) bottleneck.

❌ The Problem in Modern Software Engineering

Software engineers manage dozens of active repositories simultaneously. Developers constantly suffer from cognitive load:

  • Leaving uncommitted/unpushed Git changes on local branches before closing laptops.
  • Accumulating gigabytes of dead build cache (node_modules, target, .venv).
  • Orphaned dev servers silently consuming local TCP ports (:3000, :5173, :8000).

✅ The IoT & Cloud Solution

DevDock IoT Sentinel transforms the developer's physical workspace by deploying an ambient Edge Hardware Station on an Arduino or Raspberry Pi:

  • Zero Screen Distraction: Real-time peripheral LED status indicator for repository hygiene.
  • Direct USB Serial & Cloud MQTT: Dual-mode support for zero-latency local sync or remote cloud telemetry.
  • Physical Hardware Interactivity: Instant visual triage without navigating terminal dashboards.

Distributed 4-tier edge-to-cloud computing pipeline.

Telemetry Dispatcher
Encodes JSON health payload
3. Protocol Layer
USB Serial / Cloud MQTT
9600 Baud / HiveMQ Broker

Data Lifecycle: When DevDock audits repositories on macOS/Windows, it evaluates dirty git branches, active ports, and cache bloat. ⚡ Electrical Safety & Current Limiting Calculation

Applying Ohm's Law ($V = I \times R$) for standard 5mm LEDs (Forward voltage $V_F \approx 2.0V$): 

V_resistor = V_supply - V_LED = (5.0V for Arduino / 3.3V for Pi) - 2.0V
I_LED (Arduino) = (5.0V - 2.0V) / 220Ω = 3.0V / 220Ω ≈ 13.6 mA  (Safe limit: 20mA per pin)
I_LED (Raspberry Pi) = (3.3V - 2.0V) / 220Ω = 1.3V / 220Ω ≈ 5.9 mA  (Safe limit: 16mA per pin)

✅ 100% Safe & Standard: 220Ω resistors protect both micro-controllers while ensuring high LED brightness.

⚡ Arduino Firmware (DevDock_Hardware_Station.ino)

          
Listens on USB Serial at 9600 Baud for 1-byte command characters:

          
// hardware/arduino/DevDock_Hardware_Station.ino
const int GREEN_LED = 2, YELLOW_LED = 3, RED_LED = 4;

void setup() {
  pinMode(GREEN_LED, OUTPUT);
  pinMode(YELLOW_LED, OUTPUT);
  pinMode(RED_LED, OUTPUT);
  Serial.begin(9600);
  digitalWrite(GREEN_LED, HIGH); // Default clean
}

void loop() {
  if (Serial.available() > 0) {
    char cmd = Serial.read();
    digitalWrite(GREEN_LED, cmd == 'C');
    digitalWrite(YELLOW_LED, cmd == 'D');
    digitalWrite(RED_LED, cmd == 'E');
  }
}

        


        

          
🍓 Raspberry Pi Edge Daemon (pi_sentinel.py)

          
Subscribes to Cloud MQTT telemetry stream over WiFi/Ethernet:

          
# hardware/raspberry_pi/pi_sentinel.py
import json, paho.mqtt.client as mqtt
from gpiozero import LED

green, yellow, red = LED(17), LED(27), LED(22)

def on_message(client, userdata, msg):
    data = json.loads(msg.payload.decode())
    status = data.get("status", "clean")
    green.off(); yellow.off(); red.off()
    if status == "clean": green.on()
    elif status == "dirty": yellow.on()
    elif status == "error": red.on()

client = mqtt.Client()
client.connect("broker.hivemq.com", 1883)
client.subscribe("devdock/telemetry/status")
client.on_message = on_message
client.loop_forever()
